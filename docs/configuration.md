# Configuration

Configuration is written in YAML and split into two parts: the **base
configuration** (`config.yaml`) and the **favorites** (any number of files in
`favorites.d/`). Scripts can generate favorites files without touching your
hand-written settings.

## Locations

```text
<config dir>/aw-manual/
├── config.yaml              # base configuration
└── favorites.d/             # favorites, any number of files
    ├── 00-ui.yaml           # created by the settings window (favorites.default_file)
    ├── 10-clients.yaml      # hand-written
    ├── 50-jira.yaml         # generated by a script
    └── 90-status.yaml
```

| Platform | Configuration | Local state (queue, logs) |
|---|---|---|
| Linux | `$XDG_CONFIG_HOME/aw-manual/` (`~/.config/aw-manual/`) | `~/.local/share/aw-manual/` |
| macOS | `~/Library/Application Support/aw-manual/` | `~/Library/Application Support/aw-manual/` |
| Windows | `%APPDATA%\aw-manual\` | `%LOCALAPPDATA%\aw-manual\` |

`aw-manual config path` prints the folder. On first start, the daemon creates
it with a commented `config.yaml`. Both parts can be kept in version control.

Changes to the files are applied **live**. An invalid `config.yaml` keeps the
last valid configuration active; an invalid favorites file keeps its last
valid version active (or is skipped). Errors are shown in the settings window
and by `aw-manual config check`. Unknown keys are errors, so typos are caught.

## JSON schemas

[`schemas/config.schema.json`](../schemas/config.schema.json) and
[`schemas/favorites.schema.json`](../schemas/favorites.schema.json) describe
both file types (schema version 1). With
[yaml-language-server](https://github.com/redhat-developer/yaml-language-server)
(VS Code YAML extension, Neovim, Helix, …), add a modeline:

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/arstulke/aw-manual/main/schemas/favorites.schema.json
```

Every file may contain `schema_version: 1`.

## config.yaml

All keys are optional; defaults are shown. The `config.yaml` created on the
first start contains exactly this, so every setting is visible there.

```yaml
schema_version: 1

server:
  url: http://localhost:5600        # a remote aw-server works as well
  bucket_id: "aw-manual_{hostname}" # {hostname} = this computer's name

favorites:
  dirs:                             # loaded in this order; relative to the configuration folder, ~ = home
    - favorites.d
    # - ~/Sync/aw-manual-favorites
  default_file: 00-ui.yaml          # new top-level favorites from the settings window (in the first folder)

hotkeys:
  popover: Ctrl+Alt+Space           # or a mouse button, e.g. Mouse4; empty/false disables
  stop: Ctrl+Alt+S
  resume: Ctrl+Alt+R
  favorites:                        # favorite ID → hotkey
    # acme/website/development: Ctrl+Alt+1

tray:
  display: template                 # icon | elapsed | since | title | template
  template: "{title} · {elapsed}"   # {title} {path} {elapsed} {since} {note}
  color_icon: true                  # tint the icon in the favorite's color

format:                             # used by the tray, popover, CLI and notifications
  elapsed: 1h 23m                   # "1h 23m" | "1:23" | "1h 23m 45s" | "1:23:45"
  time: 24h                         # 24h | 12h

notifications:
  idle_reminder: 15m                # false to disable
  long_running: 3h                  # false to disable
  after_restart: 1m                 # after a (re-)start: ask what you did if aw-manual was stopped at least 1m; false to disable
  after_unlock: 1m                  # after unlocking: ask what you did if the screen was locked at least 1m; false to disable
  offline: true                     # tell me when entries are buffered (aw-server unreachable)
  work_hours:                       # for the idle reminder
    days: [mon, tue, wed, thu, fri]
    from: "08:00"
    to: "18:00"

popover:
  scroll:
    confirm_with_hotkey: true       # pressing the popover hotkey again confirms
    dwell_time: false               # e.g. 2s: confirm when an item stays highlighted that long; false to disable
    open_at_cursor: true
    start_at: running               # running | first
    horizontal: false               # horizontal scrolling / wheel tilt: right = confirm, left = confirm with a note

cli:
  autostart_daemon: true            # the CLI starts the daemon if needed

log:
  level: info                       # error | warn | info | debug | trace
```

Times of day must be quoted (`"08:00"`). `favorites.default_file` is a file
name (no folders) ending in `.yaml` or `.yml`.

aw-manual writes heartbeats every 60 s and creates its bucket with the type
`manual.activity`; neither is configurable.

### Durations

A duration is one or more `<number><unit>` parts: `500ms`, `30s`, `15m`,
`1h30m`, `1h 30m`, `1.5h`, `1d`. Units: `ms`, `s` (`sec`), `m` (`min`), `h`
(`hr`), `d`. A number without a unit is an error. All duration settings must be
longer than 0 and can be disabled with `false`.

| Setting | Notes |
|---|---|
| `notifications.idle_reminder`, `notifications.long_running` | |
| `notifications.after_restart` | aw-manual records every 15 s that it is running, so stops are measured to about 15 s |
| `notifications.after_unlock` | The lock state is checked every 2 s, so shorter locks may go unnoticed |
| `popover.scroll.dwell_time` | Disabled by default. Scroll mode closes after 10 s without input (longer when the dwell time needs it) |

## Hardware devices

Hardware input devices are **off by default**. Supported:

| Driver | Device | Connection |
|---|---|---|
| `timebuzzer` | timeBuzzer (button, rotary ring) | USB MIDI, Linux only |

No hardware IDs or `/dev` paths are built in. `aw-manual devices setup` walks
you through it (choose the connected device, test it by using it, change
bindings if you like) and writes the result into `config.yaml` while keeping
your comments. Or look up what is connected and select it in `config.yaml` by hand:

```sh
aw-manual devices setup [driver]   # interactive: pick, test and save
aw-manual devices list              # drivers, their inputs, connected devices with usb_id and node
aw-manual devices monitor timebuzzer   # print every input and the action it triggers
```

```yaml
devices:
  timebuzzer:
    enabled: true
    device:                         # at least one of name, usb_id, path; all given ones must match
      usb_id: "1234:abcd"           # from `aw-manual devices list`
      # name: timeBuzzer            # part of the card name (case-insensitive)
      # path: /dev/snd/midiC5D0     # fixed node; card numbers change between plug-ins
    long_press: 600ms               # a press at least this long is `long_press`
    bindings:                       # these are the defaults
      press: popover                # open the popover, or confirm when it is open
      long_press: stop
      turn_left: prev               # navigate the open popover
      turn_right: next
      hover_start: open             # hand above the buzzer: open the popover (never confirms)
      hover_end: close              # hand leaves: close the popover if hover_start opened it
```

Actions: `popover`, `open` (opens the popover, never confirms), `close` (closes a popover that `open` opened, as long as nothing was
confirmed in it, so a note field you are typing into stays), `stop`, `resume`, `next`, `prev`, `confirm`, `back`,
`cancel` (the last five only act on an open popover), `favorite:<id>`, and
`none` (or `false`) to unbind an input. With the defaults the device operates
the popover's scroll mode: press, turn to the activity, press again.
Entries are recorded with `source: device`.

The daemon reconnects when the device is plugged in later or removed, and
applies changes of the `devices` section without a restart. Reading the
device node needs access to `/dev/snd` (usually the `audio` group or the
active seat's ACL); `devices list` tells you if it is not readable.

## Favorites files

Each file in `favorites.d/` contains favorites under the key `favorites`.
Files ending in `.yaml` or `.yml` are loaded; hidden files (`.*`), temporary
files (`*~`, `*.tmp`) and subfolders are ignored.

Every node has an ID (stable, used by the CLI, hotkeys and in ActivityWatch),
a title, and optionally a color, an icon, and (leaves only) a kind:
`activity` (default) or `status` (break, meeting, focus, …). Nodes with
children are folders; **only leaves can be started**.

### Compact notation (hand-written)

Keys are titles, nesting is the hierarchy, properties start with `_`:

```yaml
favorites:
  ACME:
    _color: "#E4572E"            # applies to ACME and everything below it
    _icon: briefcase
    Website:
      Development:
        _icon: code              # overrides the inherited icon
      Code Review:               # empty value = leaf
    Internal Tools:
      _color: "#3B82F6"
      _id: tools                 # explicit ID instead of "internal-tools"
      Maintenance:
  Break:
    _kind: status
    _icon: coffee
```

- Properties: `_id`, `_color`, `_icon`, `_kind`, `_ask_note`. Unknown `_`
  keys are errors.
  Titles must not start with `_`.
- A node is a **leaf** if its value is empty or contains only properties
  (`Development: {_icon: code}`); as soon as it has a child, it is a folder.
- **List shorthand** for leaves without properties:
  `Website: [Development, Code Review, Deployment]`.
- **IDs** are derived from titles as slugs ("Code Review" → `code-review`,
  "Büro" → `buro`) unless `_id` is set; full IDs join the levels with `/`
  (`acme/website/code-review`). Renaming a title changes its ID, so set `_id`
  for favorites you bind to hotkeys or rename often
  (`aw-manual config check --strict` lists leaves without `_id`).
- Quote titles with YAML special characters: `"WEB-123: Checkout bug":`.
  Colors must be quoted (`"#E4572E"`) because `#` starts a comment.
- Duplicate titles in a folder, or two titles with the same slug, are errors.
- The order is the written order.

### Explicit notation (for generators)

```yaml
# generated by jira-sync – do not edit by hand
generated: true                     # read-only in the settings window
parent: acme/website                # optional; default: top level
favorites:
  - id: web-123
    title: "WEB-123 Checkout bug"
  - id: web-140
    title: "WEB-140 New footer"
    icon: bug
    children: []                    # optional; leaves have no or empty children
```

Fields: `id` (required), `title` (required), `color`, `icon`, `kind`,
`ask_note`, `children`. IDs may contain letters, digits, `.`, `_` and `-`. The resulting
full IDs here are `acme/website/web-123` and `acme/website/web-140`.

### Asking for a note

`_ask_note: true` (explicit notation: `ask_note: true`) makes a favorite ask
for a note whenever it is started from the popover, the tray menu or a hotkey,
e.g. a generic "Ticket work" favorite that needs the ticket number:

```yaml
favorites:
  ACME:
    Tickets:
      _ask_note: true          # every leaf below asks for a note
      Bug fixing:
      Review:
        _ask_note: false       # except this one
```

The popover then opens with the note field; Enter starts the favorite with the
note (an empty note starts it without one), Esc cancels. The CLI never asks
(use `--note`).

### Inheritance

`color`, `icon` and `ask_note` are inherited from the nearest ancestor that
defines them; a child overrides them with its own value. `kind` is not inherited and only
allowed on leaves. With `parent`, favorites inherit from the referenced folder.
`aw-manual list --json` shows the resolved values, marked `own` or `inherited`.

Icons are shown as emoji in the popover; known names include `briefcase`,
`code`, `coffee`, `bug`, `book`, `calendar`, `chart`, `chat`, `design`, `doc`,
`mail`, `focus`, `globe`, `home`, `lunch`, `meeting`, `phone`, `pause`,
`rocket`, `review`, `server`, `settings`, `star`, `support`, `test`, `tools`,
`travel`, `write`, `idea`, `money`, `learn`, `music`. You can also write an
emoji directly (`_icon: "🎯"`).

### Merge rules

- Order: folders in the order of `favorites.dirs`, files by file name, entries
  in written order. Numeric prefixes (`10-`, `50-`) control the order.
- `parent` (full ID of a folder or leaf) attaches a file's favorites below a
  node defined in a file that loads **earlier**; they are appended after the
  node's existing children. Both notations support `parent` and `generated`.
- If `parent` is a **leaf**, it becomes a folder as soon as the file adds at
  least one favorite to it (its `kind` no longer applies, and it can no longer
  be started). This lets you define the rough structure by hand and let a
  generated file fill in the final leaves, e.g. `10-clients.yaml` defines
  `ACME › Tickets` as a leaf and `50-jira.yaml` (`parent: acme/tickets`) adds
  the tickets below it. While the generated file is missing or empty, the leaf
  stays startable.
- A file is **rejected as a whole** if it defines a full ID that already
  exists (the error names both files; the earlier definition stays), if its
  `parent` doesn't exist, or if it is invalid. Other files keep working.

### Tips for generators

- Use the explicit notation and `generated: true`.
- Write atomically: write a temporary file (e.g. `.50-jira.yaml.tmp`), then
  rename it.
- Keep IDs stable across runs (derive them from ticket keys, not titles).

## Settings window

Tray → Settings… (or `aw-manual settings`) edits the same files:

- Base settings are written to `config.yaml`. Only changed values are
  rewritten; comments, order and formatting are kept. Invalid values are
  rejected before anything is written.
- Favorites are added to the file that defines the chosen folder; new
  top-level favorites go to `favorites.default_file` (`00-ui.yaml`) in the first
  favorites folder unless you pick another file. Favorites can be removed from the file that defines them. Files with
  `generated: true` are read-only.
- Parts of a file written in a layout the editor doesn't handle (for example
  `{…}` flow mappings) produce a message asking you to edit the file by hand.
